# 개발 워크플로우

## 필수 프로세스

모든 기능 추가, 수정, 리팩토링은 아래 4단계를 반드시 따른다.

---

## 1단계: 계획 수립

작업 요청을 받으면 코드 작성 전에 다음 항목을 포함한 계획을 작성한다.

- **작업 범위**: 어떤 파일을 생성/수정하는지
- **레이어 설계**: 어느 레이어에 무엇을 추가하는지 (Controller / Facade / Service / Infrastructure / DTO)
- **영향 범위**: 변경이 기존 코드에 미치는 영향
- **예상 체크리스트**: 완료 후 검증할 항목

예시 출력 형식:
```
## 계획

### 작업 범위
- `src/modules/baekjoon/service/baekjoon.service.ts` 생성
- `src/modules/baekjoon/infrastructure/baekjoon.api.ts` 생성

### 레이어 설계
- Infrastructure: solved.ac REST API 어댑터 구현
- Service: 문제 풀이 통계 집계 로직

### 영향 범위
- dashboard.facade.ts에 baekjoon 데이터 추가 필요

### 완료 후 체크리스트
- [ ] API 응답 DTO 타입 일치 여부
- [ ] 에러 핸들링 (NotFoundException / InternalServerErrorException)
- [ ] 기존 대시보드 응답 구조 유지
```

---

## 2단계: 사용자 승인

계획을 제시한 후 **반드시 사용자의 명시적 승인을 받는다.**

- 승인 전 코드 작성 절대 금지
- 계획 수정 요청 시 수정된 계획을 다시 제시하고 재승인 요청

---

## 3단계: 개발

승인된 계획의 범위 내에서만 개발한다.

- 계획에 없던 파일 생성/수정 금지
- 요청하지 않은 리팩토링, 기능 추가 금지
- 코드 스타일은 [code-style.md](./code-style.md) 준수

---

## 4단계: 완료 후 검증

개발 완료 후 체크리스트를 직접 검증하고 결과를 보고한다.

### 공통 검증 항목

- [ ] 컴파일 에러 없음 (`tsc --noEmit` 수준 검토)
- [ ] 아키텍처 레이어 규칙 준수 (레이어 간 의존 방향 확인)
- [ ] DTO 타입이 실제 API 응답과 일치
- [ ] 에러 처리 누락 없음
- [ ] 기존 기능 동작에 영향 없음
- [ ] 불필요한 `console.log`, 미사용 import 제거

### 보고 형식

```
## 완료 보고

### 변경 파일
- `경로/파일명`: 변경 내용 요약

### 체크리스트
- [x] 컴파일 에러 없음
- [x] 레이어 규칙 준수
- [x] 에러 처리 완료
- [ ] (미완료 항목이 있으면 사유와 함께 기재)
```
